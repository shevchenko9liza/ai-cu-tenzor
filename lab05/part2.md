# Лаборатория 5 · задания 4–6

Статус: проектное предложение агента по выбранному пользовательницей сценарию. Связи с [US1–US5](part1.md). Реальное пользовательское тестирование ещё не проводилось.

## C1. Разобрать согласованный набор

Цель: получить обоснованный следующий шаг. Инициатор: инженер станции. Условие: выбран учебный набор A с указанными метаданными и журналом событий. Результат: технические условия в учебном примере согласованы; нужен отдельный проект эксперимента.

| Шаг | Действие инженера | Видимый ответ продукта |
|---|---|---|
| 1 | Выбирает набор A | Объект, период, цель; указание на учебные данные |
| 2 | Открывает паспорт | Параметры, время и журнал событий; происхождение всех значений обозначено как демонстрационное |
| 3 | Запускает проверку | Замечания и ограничения; нет реального серверного анализа |
| 4 | Читает вывод | «Можно готовить эксперимент» с оговоркой: качество прогноза ещё не проверено |
| 5 | Готовит план | Разобрать отказ, согласовать задачу, горизонт и способ оценки; проверить доступность признаков до события |
| 6 | Сохраняет план либо возвращается | Текстовый файл с набором, выводом и ограничениями; доступен возврат |

## C2. Уточнить метаданные и продолжить

Цель: снять исправимую неопределённость, не выдать догадку за факт. Условие: набор B, часовой пояс неизвестен. Результат зависит от наличия подтверждённого пояса.

| Шаг | Действие инженера | Видимый ответ продукта |
|---|---|---|
| 1 | Выбирает B, читает паспорт и запускает проверку | «Нужно уточнить время» и причина: нельзя надёжно сопоставить сигнал и событие |
| 2 | Переходит к уточнению | Поле пояса, варианты «Не знаю» и «UTC+3 подтверждён владельцем архива» |
| 3а | Выбирает известный пояс | Уточнение сохранено для учебного набора; предлагается повторная проверка |
| 4а | Повторяет проверку | Новый вывод и пометка об уточнении; старый результат заменён |
| 3б | Оставляет «Не знаю» | Подтвердить нельзя; доступен план запроса сведений владельцу |
| 5 | Сохраняет следующий шаг | В исправленном случае — план эксперимента; в неизвестном — запрос пояса и правила времени |

Возврат к паспорту сохраняет выбор текущего набора. Выбор другого набора сбрасывает его уточнения и результат. Нельзя получить положительный вывод для B простым переходом назад/вперёд.

## C3. Получить отрицательный результат

Цель: понять, почему пока нельзя оценивать прогноз отказов. Условие: набор C без журнала событий. Результат: список недостающих материалов и адресат запроса по роли.

| Шаг | Действие инженера | Видимый ответ продукта |
|---|---|---|
| 1 | Выбирает C, изучает паспорт | Показания есть, журнал событий отсутствует |
| 2 | Запускает проверку | «Нужна история событий»; нельзя проверить, какие предупреждения предшествовали отказам |
| 3 | Читает ограничения | Это ограничение проверки прогноза отказов, не запрет всех видов анализа |
| 4 | Готовит следующий шаг | Запросить дату/время, оборудование, вид события, ремонт, источник и достоверность записи |
| 5 | Сохраняет план | Отрицательный результат и причина сохранены; нет фиктивной кнопки «всё исправлено» |

Пользователь может выбрать другой готовый набор. Настоящая загрузка журнала и изменение задачи исследования в макет не входят.

## 5. Общая карта

Выбор архива → паспорт → проверка → вывод → план.

Из проверки B: уточнить пояс → повторная проверка; «не знаю» → запрос владельцу. Из проверки C: ограничение цели → запрос истории событий. Из любого шага: назад к паспорту; смена набора → очистка результата. Пустой старт → понятная просьба выбрать пример.

| US | Сценарии | Экран/состояние и переход |
|---|---|---|
| US1 | C1–C3 | Выбор и паспорт |
| US2 | C1–C3 | Паспорт и проверка |
| US3 | C2 | Уточнение пояса, повтор, неизвестный пояс |
| US4 | C1–C3 | Три разных вывода с ограничениями |
| US5 | C1–C3 | План, сохранение, возврат |

Собственный интерфейс выбран для конкретной рабочей задачи инженера: разобраться в состоянии набора и получить согласуемый следующий шаг. Проверить, нужен ли отдельный интерфейс вместо существующих инструментов, предстоит на кастдеве.

## 6. Прототип и проверка

[Открыть отдельный HTML-прототип](prototype.html). Реальные ИИ, сервер и файлы станции не подключены. [ФТ и НФТ](requirements.md) описывают ожидаемое поведение. Технические проверки агента записываются отдельно от [личного журнала](decisions.md).

Личный проход 1: набор A → паспорт → проверка → план → сохранение. Объяснить своими словами, что уже проверено и чего ещё недостаточно для обещания прогноза.

Личный проход 2: набор B → замечание о времени → попытка оставить неизвестное → подтверждённый пояс → повторная проверка → новый план. Проверить также отрицательный C: результат не должен предлагать запуск модели.

Зафиксировать фактические действия, ожидание, наблюдение и решение после проверки. Эти строки не заполнены за студентку.
