Техническая проверка прототипа

Проверяет агент, 25.10.2026. Это проверка поведения интерфейса на учебных примерах, не личное прохождение студентки, не пользовательское исследование и не анализ промышленного архива.

Воспроизведение

Для просмотра установка не нужна: открыть archive-check.html в браузере. Все стили, данные и логика находятся в одном файле; сеть не требуется. Выбор, уточнения и поля плана хранятся до перезагрузки вкладки. При смене набора с записями есть предупреждение с отменой или подтверждением сброса.

Для повторной технической проверки из корня репозитория нужны Node.js, зависимости package.json и Chromium для Playwright:

npm install
npx playwright install chromium
npm run build
npm test

При подготовке использованы уже установленные зависимости среды: Node.js 24.22.1, marked 17.0.5, Playwright 1.62.1. Установка из npm на чистой машине в этой работе не выполнялась. Проверка браузера выполняется через локальный file://, в контексте с отключённой сетью. Скрипт: scripts/check-prototype.mjs. Скриншоты и отчёты запусков сохраняются локально в .private/qa/. Машиночитаемый результат текущей проверки опубликован отдельно в verification-results.json.

Проверяемые условия

  1. Пустой выбор блокируется с понятной ошибкой.

  2. C1 показывает технический вывод с ограничениями; паспорт содержит метку времени и единицы.

  3. Возврат сохраняет выбранный набор.

  4. Файл C1 содержит текущий набор, вывод и ограничения.

  5. В C2 можно оставить неизвестный пояс и подготовить запрос.

  6. Неизвестный пояс нельзя сохранить как подтверждённый.

  7. После уточнения требуется повторная проверка.

  8. Повтор заменяет прежний результат C2.

  9. Скачивание C2 содержит актуальное уточнение.

  10. Смена набора очищает уточнения и старый результат.

  11. C3 остаётся отрицательным после возврата и повторной проверки.

  12. Файл C3 сохраняет отрицательный вывод и состав запроса событий.

  13. На ширине 390 px проверенные экраны не имеют горизонтальной прокрутки страницы.

  14. Выбор и основной переход работают с клавиатуры; фокус переходит к новому заголовку.

  15. HTML-отчёт открывает отдельный прототип в автономном режиме.

  16. Во время этих проходов нет ошибок JavaScript и HTTP-запросов.

  17. Наблюдаемые переходы укладываются в предложенную цель 1 секунда.

  18. Карточки содержат объект, период и заданную цель.

  19. Ограничения разбиты на пункты и объясняют период проверки.

  20. Поля плана пусты до ввода и сохраняют текст при возврате.

  21. Выгрузка содержит введённые ответственного, срок и результат без автоматического назначения.

  22. Отмена смены архива сохраняет заполненный план.

  23. Статус уточнения B виден явно; поля запроса не переходят в план эксперимента.

  24. Повторные выгрузки B завершаются с одинаковым актуальным содержимым.
