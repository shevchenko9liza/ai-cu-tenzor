# Функциональные и нефункциональные требования

Статус: версия после замечаний из переданного отчёта, 25.10.2026. Требования относятся к учебному интерфейсу. Производственные пороги пригодности архива не установлены. Все числовые цели UX ниже — предлагаемые условия проверки, а не результаты замера.

## Цепочка ценности — 7 шагов

Получить поручение оценить архив → выбрать оборудование и задачу → определить состав набора → разобраться в ограничениях → уточнить доступные сведения → получить вывод с границами → подготовить следующий шаг для решения руководителя.

Момент предполагаемой ценности: инженер может объяснить, что мешает эксперименту и какие действия нужны до вложений. Подтверждение этой ценности — отдельный кастдев.

|---|---|---|---|

| F1.2 | C1 | Блокировать продолжение без выбора | Показано сообщение у выбора |
| F1.3 | C1 | Показывать состав и источник учебного набора до проверки | Параметры и события доступны |
| F1.4 | C1 | Выводить технический результат отдельно от пригодности модели | Ограничения разбиты на пункты; объяснены горизонт и период проверки; нет обещания точности или предотвращённого отказа |
| F1.5 | C1 | Создавать план следующего шага по текущему выводу | В плане есть действия и пустые поля ответственного, срока и результата для ручного согласования |
| F1.6 | C1 | Сохранять набор, статус, вывод и поля плана в текстовый файл | Содержимое совпадает с экраном; незаполненные значения обозначены как несогласованные |
| F2.1 | C2 | Выявлять неопределённый пояс у учебного B | Видна причина невозможности сопоставления времени |
| F2.2 | C2 | Предлагать уточнение и вариант «Не знаю» | Поле названо «Часовой пояс показаний», доступен запрос без догадки |

| F3.3 | C3 | Сохранять доступ к показаниям и объяснению | Отрицательный вывод не превращает весь экран в ошибку |
| F3.4 | C3 | Не имитировать получение отсутствующего журнала | Нет кнопки, снимающей препятствие без сведений |
| F3.5 | C3 | Формировать запрос с необходимыми полями событий | В плане перечислены время, объект и тип события |

## Нефункциональные требования

| ID | Сценарий | Категория | Проверяемое условие |
|---|---|---|---|
| N1.1 | C1 | Совместимость | Самодостаточный HTML открывается локально в Chromium без сервера и сети |
| N1.2 | C1 | Удобство | При ширине 390 px основные действия доступны без горизонтальной прокрутки страницы |
| N1.3 | C1 | Приватность | Макет не отправляет сетевых запросов и не принимает реальные архивы |
| N1.4 | C1 | Производительность | После нажатия локальный экран обновляется не позднее 1 секунды в проверяемом браузере |
| N2.1 | C2 | Надёжность | Возврат сохраняет текущий выбор и поля плана; подтверждённая смена набора очищает результат и поля. Записи запроса B не переносятся в план эксперимента |
| N2.2 | C2 | Удобство | Ошибка подписана текстом и связана с полем; основные элементы доступны с клавиатуры |
| N2.3 | C2 | Совместимость | Исправление и повтор выполняются в том же автономном файле без сторонних ресурсов |
| N3.1 | C3 | Удобство | Отрицательный вывод объясняет ограниченную цель и следующий шаг, не использует один цвет вместо текста |
| N3.2 | C3 | Надёжность | Повторные переходы не снимают отсутствие журнала и не создают положительный результат |
| N3.3 | C3 | Приватность | Макет не отправляет поля плана по сети. В учебной проверке в поля вводят только демонстрационные сведения; реальные данные не требуются |

Рассмотрены все шесть категорий из REQ: производительность, надёжность, безопасность/приватность, удобство, масштабируемость, совместимость. Масштабируемость многопользовательского сервиса не проверяется этим локальным макетом; придумывать нагрузку и серверное SLA не требуется. Промышленная безопасность, права доступа и защита настоящего архива будут отдельными требованиями после согласования реального пилота.
